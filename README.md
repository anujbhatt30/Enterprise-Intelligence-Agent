# 🧠 Enterprise Intelligence Agent

A multi-tool AI agent that reasons over company documents and databases —
and automatically picks the right tool for the question. Ask it to
summarize a policy, pull a sales figure, analyze a trend, or explain
*why* something happened, and it routes the question to the right
capability on its own.

Runs **entirely locally** via [Ollama](https://ollama.com) — no API key,
no cloud calls, no cost per query.

```
"Summarize the company's leave policy."                        → RAG
"What were total sales in Q4?"                                  → SQL Agent
"Which product category grew fastest?"                          → SQL + Python
"Why did sales decline and what should management do?"          → Reasoning
```

## Overview

Most "chat with your data" demos only do one thing — search documents,
*or* query a database. Real business questions rarely stay in one lane:
answering "why did sales decline and what should we do about it"
requires pulling numbers, analyzing them, and reasoning about the
result, not just running a single query.

This project builds that as a working system: a **router** classifies
each incoming question and dispatches it to one of four tools, each
built and tested independently before being wired together.

| Tool | Handles | Example |
|---|---|---|
| **RAG** | Document / policy questions | "How many sick days do I get?" |
| **SQL Agent** | Direct factual/numeric questions | "What were total sales in Q4?" |
| **SQL + Python** | Trend, growth, ranking questions | "Which category grew fastest?" |
| **Reasoning** | "Why" and recommendation questions | "Why did sales drop, and what should we do?" |

## Tech Stack

- **Python** — core language
- **Ollama** (`qwen3.5:9b`) — local LLM for generation, SQL writing, and reasoning
- **scikit-learn** — TF-IDF retrieval for the RAG pipeline
- **SQLite** — sample structured database (swappable for Postgres/MySQL)
- **pandas** — computation layer for trend/growth analysis

## Setup

**1. Clone the repository**
```bash
git clone https://github.com/<your-username>/enterprise-intelligence-agent.git
cd enterprise-intelligence-agent
```

---

**2. Install Python dependencies**
```bash
pip install -r requirements.txt
pip install ollama streamlit
```
---

**3. Install Ollama and pull a model**
```bash
# Install from https://ollama.com, then:
ollama pull qwen3.5:9b
```

**4. Build the sample data**
```bash
python sql_agent/create_db.py     # sample sales database
python rag/ingest.py              # RAG document index
```

## Usage

**Run the full app (recommended):**
```bash
streamlit run app/app.py
```
Opens a chat interface in your browser. Click an example question in the
sidebar or type your own — the router shows which tool it picked before
returning the answer.

**Run individual components directly (for testing/debugging):**
```bash
python rag/generate_ollama.py         # RAG only
python sql_agent/sql_agent_ollama.py  # SQL agent only
python sql_agent/analysis_ollama.py   # Analysis layer only
python router/router_ollama.py        # Full router, runs 4 example questions
```

## How It Works

1. **Classification** — the router sends the question to the LLM with a
   short description of each of the 4 categories and asks it to pick one.
2. **Dispatch** — based on the category, the router calls the matching
   module:
   - `RAG` → retrieves the most relevant document chunks (TF-IDF cosine
     similarity), then asks the LLM to answer using only that context,
     citing the source file.
   - `SQL` → the LLM writes a SQL query against the known schema, which
     is checked against a blocklist (no `INSERT`/`UPDATE`/`DELETE`/
     `DROP`/etc.) before executing, then the result is explained in
     plain English.
   - `ANALYSIS` → raw data is pulled via SQL, aggregated with pandas
     (e.g. quarter-over-quarter growth per category), and the *computed
     table* — not raw rows — is handed to the LLM to interpret.
   - `REASONING` → gathers the same computed data as the analysis layer,
     then asks the LLM to explain likely causes and give concrete,
     data-grounded recommendations.
3. **Answer** — returned to the user along with which tool handled it,
   for transparency.

## Verified Results

Each component was built and tested independently before integration.

**RAG** — query *"How many days of annual leave do employees get?"*
correctly retrieved the Annual Leave section as the top match
(cosine similarity 0.61).

---

**SQL Agent** — tested against a 600-row sample sales database:
- *"What were total sales in Q4 2025?"* → **$189,729.86** (verified against a manual query)
- *"Which product category had the highest total sales?"* → **Electronics, $577,090.59** (verified)
- Safety guardrail confirmed: a `DROP TABLE` query was correctly blocked before execution

---

**SQL + Python Analysis** — quarter-over-quarter growth by category:

| Category | Q1 2025 | Q4 2025 | Growth |
|---|---|---|---|
| Stationery | $2,542.98 | $3,214.18 | **+26.4%** |
| Furniture | $51,020.33 | $64,162.20 | **+25.8%** |
| Electronics | $132,906.26 | $122,353.48 | **−7.9%** |

Notably, Electronics has the *highest total sales* but is actually
*shrinking* — a good example of why "highest total" and "fastest
growing" require different tools to answer correctly.

---

**Router** — successfully classified and answered all 4 example
questions from the original project spec, routing each to the correct
tool end-to-end.

## Limitations & Future Work

- **Classification isn't perfect.** A 9B local model occasionally
  misclassifies ambiguous questions (e.g. ones that mix a factual and a
  "why" component). The router prompt includes a few-shot example set
  that can be extended as new edge cases are found.
- **TF-IDF retrieval is a baseline**, not semantic search — it won't
  match phrasings like "time off" to "annual leave" as well as an
  embedding-based approach would. See the upgrade note in `rag/ingest.py`.
- **SQL safety is a basic regex blocklist**, sufficient for a portfolio
  project but not production-grade. A real deployment should use a
  dedicated read-only database connection as well.
- **Planned next steps:** citation of specific chunks/sections (not just
  filenames), a feedback (👍/👎) loop on answers, and support for PDF/DOCX
  source documents in addition to `.txt`.
